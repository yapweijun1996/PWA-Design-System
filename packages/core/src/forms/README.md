# Native form families

Import individual factories from `@pwa-design-system/core/<name>` and the package CSS export as configured by the package. These are framework-independent DOM factories. Each returns `{ element, destroy() }`; `destroy()` removes the factory's own listeners (none in these native controls) and, for Form Field, restores the pre-existing `aria-describedby` and `aria-invalid`. The caller owns mounting and removal. Use normal DOM input/change events; controls never inject HTML. Values and labels are text.

- `createInput({ id, name?, ariaLabel?, type?, value?, placeholder?, disabled?, required?, size? })` creates a native text, email, password, search, tel or URL input. Defaults: `type: 'text'`, empty value, enabled, optional, `size: 'md'`.
- `createTextarea({ id, name?, ariaLabel?, value?, placeholder?, rows?, disabled?, required?, size? })` defaults to empty, three rows, enabled, optional and `md`.
- `createSelect({ id, name?, ariaLabel?, options, value?, disabled?, required?, size? })` uses a native single select. Options are `{ value, label, disabled? }`; values must be unique strings. The browser selects the first available option unless a value is supplied. `size` defaults to `md`.
- `createCheckbox({ id, label, name?, value?, checked?, disabled?, required?, size?, error? })` returns a wrapper containing a visible label and `.input`; defaults unchecked, enabled, optional. `setError(message?)` links a visible validation message. Native Space toggles it.
- `createSwitch(...)` accepts the checkbox options and returns the same shape with `role="switch"`. Its stable label does not change with state; native checked state is authoritative.
- `createRadioGroup({ id, legend, name, options, value?, disabled?, required?, error? })` returns a `fieldset` and `.inputs`; each option is `{ value, label, disabled? }`. Defaults: no selected value, enabled, optional, no error. `setError(message?)` links a visible validation message to the choices. Native same-name grouping and arrow keys apply. Radio choices have one presentation and inherit the default touch target.
- `createFormField({ label, control, description?, error? })` connects a visible label to an input, textarea or select with a valid unique ID. The returned `setError(message?)` updates visible text and `aria-invalid`/`aria-describedby`; an empty or omitted message clears it. Existing descriptions and invalid state are restored on `destroy()`. Checkbox/radio controls provide their own labels and are intentionally not wrapped by Form Field. Controls with an existing `aria-label` or `aria-labelledby` are rejected because those names override the visible label; remove the override before creating the field.

All controls have one visual variant. Text controls and select support `sm`, `md`, `lg`; `md` is default. Checkbox and switch support `sm`, `md`, `lg` graphics while retaining the same minimum label target; radio groups and Form Field inherit their contents. Loading and empty states are not meaningful for these native controls; show status in the surrounding form. Pass `disabled` or `required` to the control, and provide a descriptive Form Field error when validation fails. `ariaLabel` is an alternative only when a visible label is unavailable; placeholders do not label controls. IDs and radio group names must be unique within the relevant document/form.

Native controls retain browser keyboard behavior. The host application decides validation timing, submission, and recovery. Automated accessibility checks and unit tests do not replace keyboard and screen reader testing.
