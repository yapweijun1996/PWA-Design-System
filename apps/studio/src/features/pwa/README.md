# Studio offline support

The production build includes a web app manifest, install icons and a service worker scoped to `/PWA-Design-System/`. Install through the browser's installation controls where supported; availability and presentation vary by browser and operating system. The worker requires HTTPS or localhost. Development mode does not register it.

The first visit requires a connection. After the worker has installed and a subsequent navigation is controlled, the built shell, Documentation, Accessibility Lab, component catalog, token editor, layout examples, theme initialization and their generated assets are available offline. A failed or incomplete first installation does not provide offline access. Theme overrides already committed to browser storage remain available; browser storage and service-worker caches can be cleared or evicted by the browser.

At build time the worker receives a deterministic version and the SHA-256 digest of each final static file, including lazy chunks and bootstraps. Installation bypasses the HTTP cache and verifies every response before adding it to the version cache. Missing, stale or altered resources fail installation and remove that incomplete cache; the previous worker remains usable. This also protects unversioned files such as `index.html` and `token-prepaint.js` from mixing across deployments. It never adds runtime requests to a cache, and does not cache query-string requests, API responses or private data. Cache reads are limited to same-origin GET requests for stored build files. Earlier build caches are retained while their open clients report they need them. Cleanup is confined to this application's cache prefix, retains the previous version for a tab that opens during the check, and defers if a client does not report its version or the set of clients changes. A browser that does not enumerate a frozen historical client remains a limitation of this approach; unknown clients that are enumerated defer cleanup.

Studio checks for updates when it becomes visible or returns online, subject to a five-minute minimum interval, and periodically while visible. These checks never refresh the page. When a new worker is waiting, Studio offers **Prepare update**. Finish any pending import and commit or cancel the token draft, then close other Studio tabs. Preparing an update never reloads the page; the message asks the user to save their work and reload when ready. The current document can still request its previous version's lazy chunks. An uncommitted draft is held in memory: route changes are blocked while a draft or import is pending, and the browser is asked to confirm a reload or tab closure. Browser crashes, forced termination and browsers that suppress the confirmation can still lose an in-memory draft. A tab that is not responding must be closed before the update can be prepared.

The production lifecycle test builds two isolated versions and serves them under the repository subpath. Run it with `npx playwright test -c tests/pwa/playwright.config.ts` after installing Playwright Chromium; set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to use an installed Chrome. Browser install prompts, iOS standalone mode and offline behavior in browsers other than tested Chromium require separate device verification.
